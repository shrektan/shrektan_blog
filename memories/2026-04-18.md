## Hugo bilingual page bundles serve images from zh canonical path

[2026-04-18] For a bilingual page bundle (`index.md` + `index.en.md` in the same directory), Hugo renders bundle-relative resources (like `![alt](img-01.jpg)`) with the **zh URL path** even inside the en page's HTML — e.g. the en page at `/en/post/.../` will emit `<img src="/zh/post/.../img-01.jpg">`. The physical file only exists under `public/zh/...`; `public/en/...` has no image copy. Functionally it works (the zh URL resolves), but it's cosmetically cross-language and marginally sub-optimal for SEO. This is pre-existing Hugo behavior, not introduced by the img-NN convention — old posts' `cover.jpg` had the same pattern. If you want per-language URLs, you'd need to either duplicate the image file into the en bundle or switch away from bundled resources to a different layout. Not worth fixing unless a concrete SEO issue surfaces.

## 配图 prompt 必须锚定文章主题，不是锚定引人注目的单句

[2026-04-18] 给博文配图时，模型（我）的典型失败模式：抓住文章里某句有画面感的表述当成主题，写出来的 prompt 视觉上成立、但扣的是文章的**衍生点**或**结尾句**，不是**核心论点**。这次给 *归根到底，是 taste* 配图时错了两次——第一次画面偏向"迭代收敛"（扣的是最后那句"一次比一次更清楚一点"），第二次画面偏向"压缩 + 留白"（扣的是副主题"什么要砍掉"），两次都被作者指出"主题没放进去"。

修正纪律：写 prompt 前**先用一句话复述文章的 thesis**（看 title + description + 标题段），然后问自己"这个画面是在扣 thesis，还是在扣 thesis 旁边某句生动的话"。前者才对。这次最终选的"两个圆相"画面，直接扣"taste 是辨识力 / 同样的工具上限天差地别"——那才是 thesis。

这条适合之后写进 `blog-coauthoring` SKILL.md Step 3.5 的 Prompt 原则段，作为一条明确的 discipline。
