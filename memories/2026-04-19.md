# 2026-04-19 — 协作写《把 AI 当人脑来用》的 learnings

## [2026-04-19] blog-coauthoring 反复踩的结构性坑（协作 AI 方法论长文时暴露）

**不要替作者加强判断**。写 AI 方法论类文章时，Claude 倾向于把素材里的开放观察加工成强断言——典型错词：**"永远解决不了"、"正确方式"、"正确姿态"、"方向是错的"、"是无效的"**。作者明确要求"不要说得太满"。规则：论断必须能从素材 / 已有 opinion 里直接映射，不能是 Claude 对素材的"升级版"。遇到倾向性判断，主动降一档（"目前没看到好方案"替代"永远解决不了"、"效果打折扣"替代"无效"、"更有效的做法"替代"正确方式"）。

**不要把 Claude 自己的词汇带进作者文本**。"**调性**" 是反复出现的典型——作者说"你把这个加到我的写作 tone 里面是有问题的"。其他高风险词：赋能 / 闭环 / 抓手 / 底层逻辑 / 正确姿态 / 护城河（管理咨询腔）。规则：写完初稿先 grep 一遍这组词，但凡出现在正文里，必须换。

## [2026-04-19] 正式观点文章 vs 个人反思随笔 — 首稿必须先确认调性

同一位作者，《归根到底是 taste》（反思型随笔）和《兜兜转转 data.table》（正式观点）是两种完全不同的调性。素材核心是"系统性洞察 / 理论框架"时（如 AI 方法论长文），**默认往正式观点写**——参照《data-table-is-the-best》《feedback-is-evolution》的严谨度，而不是 taste 那种散文感。开头不要"我踩过不少坑 / 分享一些经验"这种水话引子——正式观点文章直接切入命题。首稿出来前向用户确认这个调性选择。

## [2026-04-19] AI 方法论文章的统一论证主线 = "人 ↔ 大模型" 类比贯穿

作者的核心观点：**大模型在本质上与人是一致的**（神经网络血统 + Transformer 把人类注意力约束数字化）。所以文章每一节都应该走"人是这样 → 所以大模型也是这样 → 所以使用 AI 要这样"三段式，开头点明"不需要记新东西，回头看自己怎么做事就行"，结尾落到"理解了自己，也就理解了大模型"。不要写成多个独立推论的罗列——那样会失去论证统一感。

## [2026-04-19] 作者对几个关键议题的精确 scope（写作时的边界）

- **"Workflow" 的精确含义**：不是"把任务拆成四个步骤分别做"，而是"有些事只能通过**迭代循环**（写→读→改→再读→再改）才能做好"。Workflow ≠ 维度拆分。
- **多模型路由的 scope = 特定场景，不是 default**：不能说"单模型是 2024 年心智模型 / 多模型是正确姿态"。正确表述：**绝大多数日常任务用一个主力模型就够了**，只在"能清晰说出 A 明显比 B 好"的特定场景做路由。
- **OpenAI 代码模型的正确叫法 = Codex / ChatGPT，不是 GPT**：Codex 是他们的代码线产品，review Claude 代码的场景用 Codex 比用 "GPT" 更准确。
- **避免"工作和副业里用 AI"这类表述**：作者在金融机构工作，"在工作中用 AI"可能触发合规敏感话题，改成"大量使用各种大模型"。

## [2026-04-19] 作者要求：复杂写作任务中途应主动起独立 agent 做 review

这次协作到后期，作者明确说"context 太多让人头晕眼花，起一个新的 agent review 一下"。这是作者文章里自己讲的"换 Agent / 换 Context = 不同文化的讨论"在写作流程里的实际应用。未来长文协作任务，在多轮迭代后主动提议或直接起独立 agent review 一次，成本低、收益高，作者明显欣赏这种操作。
