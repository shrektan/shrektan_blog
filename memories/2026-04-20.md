## GSC「备用网页（有适当的规范标记）」不是错误，是状态

[2026-04-20] Google Search Console 的「网页未编入索引」报告把**真错误**和**正常状态**混在一起，很容易误判。分辨规则：

- **真错误**（要动代码）：标题带「404」「重定向异常」「无法抓取」「服务器错误」「已屏蔽」。
- **正常状态**（不要碰）：
  - 「备用网页（有适当的规范标记）」= Google 识别出镜像/别名域并正确地以 canonical 为准，不重复收录。
  - 「已抓取 - 尚未编入索引」= 抓到了，但 Google 判断价值不够，暂不收录。
  - 「已发现 - 尚未编入索引」= 排队中，没抓。

按「验证修复」是**status-class 项目的陷阱**：点了之后 Google 会重抓，发现状态没变（因为 by design 就是这样），报告「验证失败」，触发邮件警报，让人误以为修复没生效——其实是**不该点**。

本 session 栽的坑：18 个 `blog.shrektan.com` URL 被报「备用网页」，前两次（commit `7981408` 和 `2134e70`）修的是不相关的真 404，这第三次点了"验证修复"后"失败"，用户误以为前面的修复没修干净，要再修。实际根源是 canonical 设计就是那样——`blog.shrektan.com` 是 `shrektan.com` 的镜像，Google 正确识别并归类。

## GSC Domain property 覆盖所有子域，无法配置排除

[2026-04-20] Search Console 的 property 有两种类型：

- **Domain property**（DNS TXT 验证）：自动覆盖 `shrektan.com` + `www.shrektan.com` + `blog.shrektan.com` + 所有子域，没有排除开关。
- **URL prefix property**（HTML/文件验证）：只覆盖指定前缀，不含子域。

本站当前是 Domain property，所以即使用户没"主动添加" `blog.shrektan.com`，它的 URL 仍然出现在报告里。要让子域从报告中消失，只能从 Cloudflare 边缘把子域 301 到主域——在 GSC 里改不了。

## 决策：blog.shrektan.com 301 到 shrektan.com

[2026-04-20] 用户决定彻底退役 `blog.shrektan.com` 作为独立内容镜像。方案：Cloudflare Redirect Rule（zone 级），匹配 `Hostname eq blog.shrektan.com`，301 到 `https://shrektan.com${http.request.uri.path}`，保留 query string。DNS 记录保留，Pages 自定义域可留可删。
